## New findings

1. **Cloud egress is per-host, and the hosts validation needs are the ones that are blocked.** In the cloud the fetcher writes `unobtainable` for most planned and every skeptic-required source; the referee then scores the core claim tier 0 and returns NO-GO, not infra. A good idea gets NO-GO because the run happened in the wrong place, and NO-GO appends to `DEAD_ENDS.md`. Change: `fetch.py --probe` writes `reachable.json`; the referee exits 4 when any required source is unobtainable for a network reason (`reason: egress|404|paywall` in the row); the fetcher is `fetch.py`, never WebFetch.

2. **Kill numbers are inert at tier 1, which is the tier every sub-$20 idea validates at.** A tier-1 row has no `value` comparable to a kill number. Under $20 the core claim needs three such rows, with no independence check. Any pain that exists has three forum posts, so a motivated author gets GO for a bad idea at the cheapest tier, and three Fable contexts produce numbers the referee never consults. Change: the core claim is never satisfied by tier 1; collapse the under-$20 path to author → fetcher → referee.

3. **The tier table is keyed on a number that does not exist when validation runs.** Validation runs before the interview, so the build budget is whatever the human types, and nothing binds it to the spec signed later. Also `.pipeline/validate/<slug>/` has no slug before `spec.json`. Change: `/jg-validate --build-usd N` writes `validated_budget_usd` and the idea text into `verdict.json`; slug from sha256(idea); `spec_check.py` exits 2 when `budget.build_usd > validated_budget_usd` and gains the verdict gate it promises but does not have today.

4. **The referee's drift rule zeroes every live source.** Tier 2 is live data; bodies differ on every fetch. Byte-hash drift fires on exactly the tier-2 rows. Change: `fetch.py` returns `{value, extracted_by, body_hash}`; drift is when the re-fetched value is absent or moves past the kill number.

5. **The stricter-number merge is undefined when setter and skeptic disagree on the measure, and exit 3 is double-booked.** "Stricter" needs the same measure, unit and direction. PIVOT is 3 in the plan and needs-human is 3 in the pipeline contract. A non-core claim below its tier but not killed matches no rule. Change: the skeptic reads the setter's measures (numbers redacted); freeze rejects a kill number whose measure is not in the claim's set; PIVOT gets its own exit; "below required tier → NO-GO for core, PIVOT for non-core".

6. **Haiku inside `ux_score.py` puts an unmetered model call in the scoring path.** `ux_score.py` runs during `score.py`, outside the cap, the live meter, the kill switch and the ledger. Change: keep `ux_score.py` pure; do the Haiku dedupe/resolve in `persona_run.py` or `feedback.py`, driver-side and metered.

7. **The `kit-eval` replay corpus contradicts principle 9.** Recorded streams are full transcripts. Change: `retro/redact.py` keeps types, usage, costs and hook events and drops every text field, with a test asserting no text survives.

8. **Pinning is still bypassable by the loop branch itself** unless the manifest is verified against `<workdir>` (finding 1). The workdir hash check is the only defence that does not depend on the planner's honesty.

## The validation design, revision 2

- GO for a bad idea: yes, at the sub-$20 tier, by construction (finding 2). At $20–100 a setter that picks a measure the idea trivially clears is still the dominant path, because the skeptic's stricter number is only stricter on the skeptic's own measure. The fix is the shared measure set, not more roles.
- NO-GO for a good idea: yes, three ways: running in the cloud (1), any live tier-2 source (4), validating at a low budget then wanting a bigger build (3).
- Cost and latency: five metered children plus a re-fetch: about $3–4 against $5, 10–25 minutes. Proportionate for a $20+ build, disproportionate under $20.
